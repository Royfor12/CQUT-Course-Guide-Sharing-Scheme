## 📁 课程目录结构

为了确保资料清晰易查，所有课程目录均统一采用以下结构进行组织：

```text
课程目录/
└── [课程名称]/
    ├── 01-历年真题/          # 期末试卷、期中试卷、样卷、模拟卷及测试题库
    ├── 02-课件与教材/        # 授课PPT、电子教材、讲义及考试大纲
    ├── 03-笔记与复习资料/     # 考前突击笔记、知识点总结、思维导图
    └── 04-实验与作业/        # 实验报告与数据表(XLSX)、平时作业及答案、课程论文、实习报告书、工程图纸
```

## 贡献 ｜ 上传资源

本仓库有以下两种贡献方式：

网页端直接上传：已登录的普通用户均有管理权限

☁️ 建议上传的资源类型：

- PDF、攻略、笔记、期末试卷、物理实验报告...

❓ 不建议上传的资源类型：

- 未整理的零散图片

- 需要长期更新的项目
- 需要单独管理的大型项目
- 可轻易检索到的电子教材
- 服务于、或与学校相关的开源软件/项目

> 此类内容可于 [CQUT-OpenProject](https://github.com/CQUT-OpenProject) 新建仓库单独管理

## 🛠️ 维护与贡献规范

> [!TIP]
> 如果看不懂以下内容，可以将网站链接提供给 AI 以协助理解

为维护仓库的整洁度与规范性，请所有贡献者在提交资料时遵守以下约定：

### 1. 课程命名

* **使用标准中文全称**：文件夹名称必须使用学校教务系统中的标准课程全称
* **避免特殊符号**：不得包含 `[ ]`、`/`、`\`、`*`、`?` 等易引起转义歧义的字符。涉及专业或类别标注时，一律使用全角括号 `【 】`（例如：`高等数学【机电】`）
* 若某课程暂无对应类型资料，如「历年真题」，则**不创建**该空白文件夹

### 2. 文件命名

为了方便按时间与类型检索，建议遵循以下文件命名约定：

| 资料类型 | 推荐命名格式 | 示例 |
| :--- | :--- | :--- |
| **历年试卷** | `[学年]_[学期]_[卷型]_[课程名].[后缀]` | `24-25_2_A_电路原理.pdf` |
| **试卷答案** | `[学年]_[学期]_[卷型]-答案_[课程名].[后缀]` | `23-24_1_A-答案_马克思主义基本原理.pdf` |
| **复习资料** | `[资料类型]_[说明]_[课程名].[后缀]` | `考前突击笔记_电路原理.pdf` |
| **实验与作业**| `[序号]_[名称]_[说明].[后缀]` | `实验02-液体表面张力系数的测定.pdf` |

### 3. 隐私保护

**保护「个人」与「他人」隐私**：在上传实验报告、平时作业或课程论文前，请务必去除个人信息（如学号、姓名、专业班级、导师名称等）

### 4. 添加水印

作为上传/维护者，你可以选择为自己上传的内容添加水印（或数字水印）。添加的水印需符合以下要求：

- 不得严重遮盖文件内容
- 不得披露任何联系方式

### 5. 核验提交

上传之前，对上传的文件进行核查，确认没有错误提交如下内容：

- 重复的文件
- 冗余的二进制文件
- 与当前科目无关的文件
- 其它路径下已存在的文件
- 侵犯他人隐私/版权的文件

### 6. Commit 规范

课程资料的提交标题采用 `动作《课程名称》 · 资料分类（可选说明）`。课程名称和分类与目录一致，涉及多个分类时按编号顺序列出，用 `、` 分隔。

| 动作 | 适用情况 |
| :--- | :--- |
| **新增** | 加入新的课程、分类或资料文件 |
| **更新** | 修改现有资料，或在原路径替换文件版本 |
| **删除** | 移除重复、失效或误传的资料 |
| **重命名** | 在同一父目录下更改文件或文件夹名称 |
| **移动** | 更改文件或文件夹所在的目录，可同时更名 |

- 示例 `新增《电路原理》 · 01-历年真题（2024–2025 学年）`
- 示例 `重命名《大学物理实验》 · 04-实验与作业（实验报告）`
- 一个提交集中处理一项变更。同一次移动或重命名放在同一提交内。项目文档等非课程文件使用 `动作 + 对象`，例如 `更新贡献规范`。
- 有可核实的来源 PR 时，在正文保留 PR 编号，例如 `来源 PR：#123`。为已核实的原贡献者署名时，在正文后空一行，每人单独写一行 `Co-authored-by: 姓名 <GitHub 关联邮箱>`。

### 7. PR 规范

- 每个 PR 聚焦一个课程或一项明确的变更。标题写明主要动作和对象，可沿用提交标题格式。
- 描述中写清涉及的课程和目录、改了什么、为什么改。删除时列出原路径，移动或重命名时列出变更前后的路径。
- 新增或替换资料时写明来源，转载资料同时注明授权情况。提交前按「核验提交」逐项检查，并在描述中列出相关 PR 或 Issue 编号。
